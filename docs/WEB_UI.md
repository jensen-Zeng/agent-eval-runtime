# 登录与项目管理（v1.4）

AgentEval Runtime 的网页服务使用 PostgreSQL 保存账号、项目、数据集版本、实验、任务和用量。服务默认绑定 loopback，适用于可信操作者在本机协作。首次访问需建立管理员账号；所有任务提交都必须归属到项目。

## 启动与首次设置

Windows 在仓库根目录运行 `scripts/start.ps1 -ConfigFile configs/local.json`；Linux 运行 `bash scripts/start.sh`。脚本会启动或复用 PostgreSQL、准备 sandbox 镜像并前台运行 Runtime。已有数据库卷继续使用原密码。浏览器打开 `http://127.0.0.1:8787/`。

首次进入时设置管理员用户名和密码。用户名为 3–64 个 ASCII 字母、数字、点、下划线或连字符，且以字母或数字开头；密码至少 12 个字符，最多 256 个字符。只有数据库尚无账号时，setup 才能创建首个管理员。之后管理员通过“账号管理”创建其他账号。服务不提供密码找回流程。

密码使用 PBKDF2-SHA256、600,000 次迭代和随机盐保存。登录会建立数据库会话；浏览器 cookie 为 HttpOnly、SameSite=Strict，最长 12 小时。退出登录会删除该会话。变更请求需要同源保护和 `X-AgentEval-CSRF: 1`；网页会自动添加此头。

## 账号、项目与角色

管理员可以创建账号、查看已登记任务目录，以及执行项目内的管理操作。管理员身份不会自动授予任何项目数据访问权：每个项目资源请求都要求用户已加入目标项目。创建项目的人自动成为该项目 Owner；管理员或其他账号需由项目 Owner 显式加入并分配角色。

| 项目角色 | 可访问内容与操作 |
| --- | --- |
| Owner | 读取项目数据；管理成员和限额；创建或版本化数据集；提交、取消实验并查看任务、事件和用量 |
| Executor | 读取项目数据；提交和取消实验；查看任务、事件和用量 |
| Reader | 读取项目数据、实验、任务、事件和用量 |

站点管理员账号的全局权限只覆盖用户、任务目录和连接配置等管理能力；访问项目范围资源时仍必须先成为项目成员。项目之间的列表、详情、实验和用量互相隔离。

网页主要包含工作区、数据集、实验、项目成员、管理员账号管理和连接设置。成员页只允许 Owner 修改成员；管理员可创建账号，但不能在未加入项目时查看其实验。

## 数据集版本

数据集版本由任务目录中的 task ID 组成，最多 200 个任务。每个版本保存任务 manifest、源码、evaluator 和镜像的冻结摘要；提交实验时会再次核对快照。已保存版本不可修改，需要新建版本。

通常由管理员先加入目标项目并取得 Owner 角色，再为项目创建初始数据集版本，以授权目录中选定的任务。此后，项目 Owner 只能基于该项目已授权任务创建新版本；需要加入其他目录任务时由管理员在项目成员权限范围内建立新版本。项目成员不能上传任意源码、评分器或 Docker 参数。

## 实验与任务

在“实验”页选择项目、数据集版本、任务子集、Agent variant 和重复次数。支持 `scripted` 与 `llm` Agent。一个数据集最多 200 个任务，一个实验展开后的任务运行数最多 500；重复次数为 1–100，variant 数量最多 20。缺省任务集为整个数据集版本。

每次提交都要求 `Idempotency-Key`。相同项目、相同 key 和相同请求会复用原实验；同一项目的 key 对应不同请求会返回冲突。其他项目的提交拥有独立作用域。实验及其任务组和额度预留在一个数据库事务中写入，避免半组提交。

实验记录可查看总体状态、逐任务状态、报告和分页执行事件，可取消实验或单个任务，并下载 JSON/CSV。取消是异步流程：已经运行的任务会在完成清理后结束。服务重启会保留排队任务并恢复其额度预留；运行中任务会按恢复策略终结并计入已使用额度。

## 配额和用量

每个项目有每日任务运行额度和同时运行上限，由 Owner 设置。每日额度按 UTC 日、按提交日期结算；一个实验中的每个 task × variant × repeat 都占一个任务运行额度。新任务提交时计入 `reserved`，且在终态前保持预留；进入 RUNNING 不会立即结算。排队期间取消会释放预留。任务正常结束或重启恢复终结后转为 `used`，包括成功、失败、运行中取消和服务重启中断。日期归属不会因任务跨日完成而改变。

并发限额只限制 RUNNING 任务，不限制排队数。运行中取消请求在任务完成及 sandbox 清理结束前继续占用并发位。用量页按天显示 `reserved`、`used`、`released`、`running`、`daily_limit` 和 `concurrent_limit`。

## 连接设置与模型 Key

OpenAI-compatible endpoint、默认模型和重试设置保存在本机 `configs/ui/provider.json`。API Key 由主密码加密到 `configs/ui/keyvault.json`；Key 不会写入浏览器存储、任务容器或实验请求。主密码至少 12 个字符。重启 Runtime 后需重新解锁密钥库。锁定时，新的模型任务需要等到密钥库解锁或被取消。

设置、解锁或调用真实模型可能产生服务商费用。提交前核对 endpoint、模型和重复次数；token 用量和成本估算不是硬性账单上限。

## 管理 API

API 与网页同源。认证状态与登录入口：

- `GET /v1/manage/auth/state`
- `POST /v1/manage/auth/setup`
- `POST /v1/manage/auth/login`
- `POST /v1/manage/auth/logout`

管理资源以 `/v1/manage` 为前缀，包括管理员的 `/users`、`/catalog`，以及 `/projects` 下的成员、数据集、实验、jobs 与 usage。具体方法、请求体和角色规则由服务实现约束；所有变更请求都需要 `X-AgentEval-CSRF: 1`。旧的无项目 `/v1/runs` 路由（包括 GET 和写请求）及其他无项目 HTTP 写入口已关闭，避免绕过授权和用量结算。可信本机 `runtime run` 可单次直接执行，不经过项目配额；演示入口为仓库脚本 `scripts/demo.ps1` 或 `scripts/demo.sh`，没有 `runtime demo` 子命令。

## 安全与限制

服务必须绑定 loopback。不要暴露到公网、不可信网络或共享托管环境；项目角色和配额不构成面向恶意租户的完整隔离。Docker 容器共享宿主 Linux 内核，Docker daemon、镜像、登记的任务和 evaluator 都属于信任边界。Harbor 原始题包需由管理员在 CLI 导入并重启服务后才能用于项目数据集；网页不接收原始题包。

全局同时运行数受服务 worker 数和 Docker 资源限制；本机 artifacts 的磁盘空间仍需维护。清理 artifacts 前先确认没有活跃任务或仍需留存的评测证据。
