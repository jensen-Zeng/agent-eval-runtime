# AgentEval Runtime v1.0 交付与使用

更新日期：2026-10-06。项目目录：`agent-eval-runtime`。运行环境为本机控制器、单个 PostgreSQL 数据库、单个 Linux amd64 Docker Engine；Windows 和 Linux 共用 Go 实现，只在启动脚本与构建目标上区分。

## 交付范围

| 能力 | v1.0 行为 |
| --- | --- |
| 单次执行 | `runtime run`：源码独立容器 → Agent 工具操作 → 实际文件差异 → 独立可信评测 → 报告与清理 |
| 持久队列 | PostgreSQL 队列、固定 worker pool、有界排队、幂等提交、排队/执行取消、优雅停机 |
| 冻结实验 | 任务 × Agent/模型配置 × 重复次数；先 preview 冻结任务/评测器/镜像/配置哈希，再带快照前提提交 |
| 实验恢复 | `--resume` 校验矩阵及快照，使用原实验 ID 和幂等 key 从 API 重同步；避免客户端中断造成重复任务 |
| 汇总 | 按 task/agent/script/model 分组，JSON/CSV 输出成功率、分数、tokens、耗时、CPU 与采样内存；未知资源与估算 tokens 单独统计 |
| 独立复评 | `runtime reeval`：验证补丁路径/类型及实际差异，在新的评测容器执行；保存补丁、来源哈希、镜像 ID、评分与清理状态；不调用模型 |
| 题包导入 | 显式选择源码目录/ZIP/TAR/TAR.GZ、UTF-8 题目及可信 grader 目录，校验后原子发布新任务，拒绝覆盖旧任务 |
| Python grader | 在独立评测容器运行原 grader，保留 partial score、checks、policy/regression evidence 和失败分类 |
| 故障恢复 | DB 时钟租约、2 秒心跳、递增 epoch、事务内校验和提交前再校验；失去租约即停止调度/取消执行 |
| 容器收敛 | 启动时 owner 清理、恢复中断记录；运行时每 5 秒检查 owner/epoch/job/run/attempt 标签并清理孤儿 |
| 观测 | 事件分页、执行/评测资源采样、队列/worker 状态、epoch、心跳时间与 reconcile counters |

这次交付完成执行计划中 M4–M6 的单机核心范围。原计划 20–30 个真实任务与付费模型实验仍属于后续 benchmark 数据建设，不把 fixture 或模拟模型结果当成真实模型能力排名。

## 一键启动

本机 Go 已安装于 `%LOCALAPPDATA%\Programs\Go\bin\go.exe`，`build.ps1` 会自动查找，无需全局 PATH。需要 Docker Desktop 使用 Linux Engine；脚本不会自动下载新 Go 工具链。

Windows PowerShell：

```powershell
cd agent-eval-runtime
.\scripts\start.ps1
```

脚本构建 `bin/runtime.exe`、启动本地 PostgreSQL、准备 `agenteval-sandbox:v1.0` 并在前台启动服务。数据库密码采用隐藏输入；如果使用已有持久卷，输入同一个密码。数据库绑定 `127.0.0.1:5432`，API 绑定 `127.0.0.1:8787`。Ctrl+C 停止控制器；数据库卷保留。脚本参数 `-Workers 2 -QueueCapacity 32` 控制容量。

Linux：

```bash
bash scripts/start.sh
```

Linux 需 Go 1.27.1 与可访问的 Docker Engine。同一套代码，不维护两份业务实现。若已准备好数据库与镜像，直接设置 `AGENTEVAL_DATABASE_URL` 后运行 `runtime serve --project . --config configs/local.json`。DSN 只放在控制器环境，不写入实验文件、任务、容器或普通日志。迁移会自动应用；迁移前备份自己的已有数据库，使用数据库本身的备份工具。

真实 OpenAI 使用前，在启动控制器的终端设置 `OPENAI_API_KEY` 和 `OPENAI_MODEL`。密钥不通过任务 API 传入；本次验收未调用付费模型。

## 重复实验与多模型比较

先用无需模型密钥的完整示例：

```powershell
.\bin\runtime.exe experiment --file examples/v1.0-experiment.json --output artifacts/demo/experiment.json --csv artifacts/demo/summary.csv --wait
# 原示例包含故意失败的 variant，退出码 2 是已完成但存在失败任务。
.\bin\runtime.exe experiment --file examples/v1.0-experiment.json --output artifacts/demo/experiment.json --wait --resume
```

修改矩阵文件，例如：

```json
{
  "schema_version": 1,
  "name": "model-comparison",
  "tasks": ["go-parser-001", "go-unique-002"],
  "variants": [
    {"agent": "llm", "model": "YOUR_MODEL_A"},
    {"agent": "llm", "model": "YOUR_MODEL_B"}
  ],
  "repeats": 3
}
```

该矩阵展开为 12 个 jobs，由服务 worker 并行执行。每次新实验使用新实验 ID；相同 output 文件已有实验时必须显式 `--resume`，避免意外覆写或重复付费。矩阵上限 1000 个 jobs、repeats 1–100；无 `--wait` 时仅提交，待后续 resume 收集结果。Ctrl+C 停止实验客户端，不隐式取消服务端任务；需要取消时使用 `runtime cancel`。

快照包括 task revision、manifest/source/evaluator SHA256、精确 image ID 和 Agent 配置 SHA256。提交前 `expected_snapshot` 不一致返回 409。题包在服务启动时缓存；修改题包须审查、更新 revision/哈希并重启服务。已有 job 在执行前还会重载校验，发现漂移记录为基础设施错误，避免用新输入冒充旧实验。冻结输入不保证 LLM、并发或测试时间完全确定。

## 导入与复评真实题目

```powershell
.\bin\runtime.exe import --project . --id task-example --source YOUR_DATASET_ROOT/source-only.tar.gz --prompt YOUR_DATASET_ROOT/prompt.md --grader-dir YOUR_DATASET_ROOT/grader
```

grader 目录只接受 `.py` 与 `*_test.go`；默认 Python entrypoint 为 `grade.py`。仅 Go hidden tests 时使用 `--grader-entry "" --required-tests TestOne,TestTwo`。`--allowed-files` 可指定生产 Go 文件；省略时取现有非测试 Go 文件，仍受任务策略限制。导入后重启控制器才能注册新任务。任务根目录的 `go.mod` 只用于隔离 benchmark 数据，源码目录仍使用自己的模块；grader 不参与 runtime 的 `go test ./...`。

原始答案、oracle patch、旧提交和模块缓存不要放进 source-only 目录。导入器不负责判断题包文本中是否包含答案，也不会替操作者审核来源授权。Python grader 是操作者提供的可信代码，运行在评测容器内；对外展示结果前应审查 grader。

公开仓库自带三个演示题包。导入自己的任务后也可运行 baseline；以下以自带演示为例：

```powershell
.\bin\runtime.exe run --task tasks/fixtures/go-parser-001/task.json --script success
```

任何已收集补丁可以独立复评：

```powershell
.\bin\runtime.exe reeval --project . --task tasks/fixtures/go-parser-001/task.json --patch YOUR_DATASET_ROOT/candidate.patch --artifacts artifacts/reevaluations
```

复评先在源码容器验证真实变化仅落在 allowed_files，再在全新的评测容器运行 grader。标准退出码：0 成功；2 有可判定的任务失败；1 基础设施、输入或客户端错误。复评报告含评分来源与 cleanup；禁止将参考补丁的复评得分作为模型成功率。

## 性能与容量

- 默认 2 workers、32 queued jobs，最多配置 8 workers/1000 排队任务；按注册任务最大内存计算，worker 内存预留超过 Docker Engine RAM 的 75% 时拒绝启动。
- 注册题包内容与哈希启动时冻结缓存，256 MiB 总缓存上限；preview/submit 不再反复扫描整个仓库。worker 执行前保留一次磁盘校验。
- 初始文件通过一次容器 exec 流式 tar 写入真实 tmpfs；不逐文件调用 Docker，也不依赖 Docker archive copy 对运行中 tmpfs 的行为。
- trace 分页按行读取并在取够一页后停止；最大 10 MiB trace、256 KiB 单事件。Docker readiness 探针在一秒内复用结果；数据库租约仍为权威校验。
- 单文件 ≤1 MiB、单 bundle ≤50 MiB、1000 文件，目录遍历也有上限。候选补丁 ≤1 MiB。当前适合小中型、依赖已准备好的 Go 任务；TiDB 等大仓库不会因版本号升级自动兼容，需要专用镜像/缓存及分包策略。
- Go evaluator 输出仍受固定上限，截断时拒绝给有效成功结论；Python grader 可将有界结构化评分写入结果文件。
- 工具输出、HTTP body、模型响应、预算、进程数、CPU、内存和 tmpfs 都有上限；达到边界记录明确错误，不静默当成成功。

测量日志与具体口径见验收文档。tar 编码基准不包含网络、容器创建和 Go 编译，不能用作整轮任务吞吐；冷编译常占主要耗时。CPU 为执行/评测容器采样的累计消耗，内存为采样峰值，不是宿主机总峰值。tokens 区分已报告、估算、未知；缺测不填零。

## 安全边界与恢复保证

Agent 容器固定非 root UID/GID 10001、只读根文件系统、NetworkMode=none、ALL capabilities drop、no-new-privileges、seccomp 必须启用；只有受限 tmpfs workspace/tmp，无宿主源码 bind mount、Docker socket、模型 key 或数据库 key。Agent 命令只在容器中执行。API 仅 loopback，拒绝跨 Origin、未知 JSON 字段与客户端指定任意路径/镜像/Docker 参数。

文件工具使用 `os.Root` 并检查 regular file，拒绝越界与特殊文件。归档导入拒绝绝对/drive/遍历路径、链接/设备、重复及大小写冲突、Windows 设备名与超限解压；忽略 `__MACOSX`、`._*`、`.git` 与缓存元数据。所有题包禁止 `.git` 元数据，可信 grader 的 baseline Git 命令还禁用 hooks 与全局配置，只对 `/workspace` 设置受控的 safe.directory。

数据库使用 30 秒 DB-clock 租约。业务写操作在同一事务持有租约共享锁，校验 process+epoch+有效期，提交前重新校验；takeover 需要排他更新，不能在旧事务中途换代。过期心跳不能续活旧租约。正常停机 drain 期间继续续租，worker 收尾后释放。异常退出的新实例等待旧租约过期，再清理归属容器，将中断任务终结为 INFRA_ERROR/取消，保留排队任务。

Docker API 不支持数据库 epoch 的原子 fencing：创建前后检查租约、打 owner/epoch/job/run/attempt 标签，再由 reconciler 收敛残留；这是有界恢复路径，不是 DB 与 Docker 的跨系统原子事务。删除仅限当前 owner 的 runtime 标签，验收证明其他 owner 保留。应用版本为 1.0.0，容器 `agenteval.runtime=v0.1` 是为兼容历史清理保留的协议标记。

平台信任本机操作者、Docker daemon、镜像和评测代码，不提供公网多租户鉴权或独立 VM 隔离。容器共享 Linux 内核；在同一评测 UID 下，恶意候选代码与测试/grader 的交互仍需要更强的评分隔离设计。本版本的 host 保护与代码修复评测验收，不等同于证明任意恶意程序无法影响评分。审查题包、保持 Docker 更新并限制操作者权限，是部署边界的一部分。
